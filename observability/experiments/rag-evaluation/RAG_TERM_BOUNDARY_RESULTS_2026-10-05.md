# RAG 术语约束开发对照与实际上下文核查

## 决定

**不采用本轮术语提示词改动。** 两组回答各有 2 份补充了摘录未提供的 PEL 英文释义，候选还在直接 NOACK 题中漏掉“不要求可靠性且允许偶发丢失”的适用条件。回答更短不作为质量收益。生产提示词、默认 HYBRID 检索、引用提示默认 OFF 均未因该实验改变。

实际检索随后核查发现：两题所选完整分块已包含 PEL 释义、NOACK 适用条件和 CLAIM 例外。**摘录对照中的资料外扩展不能直接推断成真实检索链路的幻觉或召回问题。** 下一轮要绑定实际检索供给，而不是继续针对小摘录调提示词。

## 对照条件

- 6 个已曝光开发场景，12 次真实 Flash 调用，3 组 AB / 3 组 BA，固定原公开摘录、问题和上下文顺序。
- 实际 `KnowledgeBaseQueryService` 提示词构建器、`RagEvidenceContext` 与 Registry；ToolAccess.NONE，同模型 `qwen3.8-flash`、温度 0.2、thinking=false、输出上限 480。
- 两臂都开启编号与引用规则，生产引用默认仍 OFF。只有一个系统提示条目变化：从“使用准确的专业术语，必要时进行解释”改成“只使用知识库支持的专业术语；知识库未提供释义时不自行补充解释”。
- 该驱动记录应用构造的 system/user/options，没有 HTTP 原始载荷抓包；未记录 finishReason，不据此声明完整输出率或截断率；不评测端到端时延。
- 84 份冻结源码/配置与本轮执行源码已复核一致，6 组 user、证据编号和捕获设置完全相同，system 仅该条目变化。来源作者 Agent 对答案复查，不称独立人审。

### 六组来源作者复查

| 场景 | 观察 |
|---|---|
| PostgreSQL 默认隔离、快照与两次查询 | 两臂都保留普通 SELECT、查询开始快照及两次查询之间提交的条件 |
| Spring 默认设置 + PostgreSQL | 两臂都给出 REQUIRED、数据库默认 RC、checked exception 默认不回滚；版本是问题给定的场景条件，body 不含来源版本元数据 |
| NOACK / CLAIM | 两臂都有摘录外 PEL 释义；B 漏掉 NOACK 适用条件 |
| 文档未给生产重试参数 | 两臂均表示无法确定生产次数/秒数 |
| 已知 NOACK + 未知生产秒数 | 两臂均回答已知部分、拒答未知部分；仍补 PEL 释义 |
| Spring proxy 内部调用 / 初始化 | 两臂保留同类调用不能依赖该注解、初始化阶段不能依赖代理的边界；不推广成内部调用从未存在事务 |

本表是开发诊断，不计算正式 Faithfulness、必要事实覆盖或引用支持百分比。单题单次结果也不能估计随机模型下的总体退化概率。

## 实际检索供给核查

`term-actual-context-20261005-r1` 使用同两道公开问题，检索全部原四份公开资料，HYBRID、rewrite=false、显式 6,000 Token 正文预算。只调用检索评测接口，**没有 Chat 生成**；返回的选中 UUID 映射到范围已确认的原始公开 DB 正文，不增加对外完整正文返回接口。

- 两题均选中相同 8 块，正文预算估算 5,797 Token；各 1 次向量查询，实际 Embedding 合计 **116 Token**（49 + 67）。
- 第一块的精确原文同时包含 `Pending Entries List (PEL)`、可靠性/丢失条件和 `NOACK\ndoes not apply for retrieved pending entries`。
- 初版词面检查误用 `apply to`，将 CLAIM 标记为 false。保留原始 `summary.json`，另存归一化原文范围的 `source-body-audit.json`，不能把字符串未匹配当成事实缺失。
- 两题选中内容在本隔离索引中覆盖整个 Redis 文档，包括不少多语言客户端签名。值得后续比较正文预算、分块与上下文去冗余，但尚未实测这些方案的收益。
- 同一轮序号复现只说明这两个受控输入；由 UUID 重建正文不等于已抓到 Chat 线上载荷，也不证明最终回答一定使用了全部事实。

## 失败、范围与恢复

- `term-generation-dev-20261005-r1` 准备阶段将 `PromptSecurityConstants` 路径写成 common/constant，实际为 common/ai；保留部分 76 份 baseline + 7 份 driver 源码，**模型调用 0**。r2 使用新目录完成，不覆盖 r1。
- 本轮局部最终审计脚本第一次假定两类源码 manifest 都有 original 字段，触发 KeyError；修正兼容 file/original 后复核 84 份。该失败为本地审计，外部模型调用 0。
- 校准与生成合计 **44 次 Chat 请求、47,989 已知 Token、用量未知 0**；另 2 次检索 / 116 Embedding Token。不能把 input/output/total 监控三条序列重复相加。
- 公开 4 文档 / 24 原向量 SHA 始终为 `76d903d460a4f34c5f3fedcc1e31b998cb999a6fb8d2ad6105760c1ed30b495b`。全隔离环境 15 文档 / 123 向量，RAG 会话/消息和语音会话均 0；无清库或替换索引。
- 恢复默认 App，Spring AI 2.0.1，TOKEN800、durable=false；当前执行 handle 7664。关闭前必须重新核对 PID、命令行与工作区，不能使用过期 PID。
- 本轮只改实验/报告文件，没有新增生产后端或前端变更；未把旧回归结果当作本轮新测试。
