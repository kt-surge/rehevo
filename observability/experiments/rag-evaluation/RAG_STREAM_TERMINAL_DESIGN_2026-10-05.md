# RAG 流式终态与停止方案（实施前源码审计与自评审）

## 当前问题

1. KnowledgeBaseQueryService 把上游错误转换为“【错误】”正文，随后 onComplete；会话层因此把失败保存成 completed=true。
2. Controller 分别在完成/错误回调保存，但没有取消出口；占位消息可能永久处理中，部分内容丢失。流状态在订阅外创建，也不适合重复订阅。
3. 前端把 EOF 当完成，没有明确终止协议；手工转义换行破坏字面反斜杠。页面回调按最后一条消息更新，切换会话时可能把旧流写到新会话。
4. 历史查询只按 completed=true 取消息，失败回答排除后对应用户问题可能孤立进入上下文；目前靠排除第一条消息猜当前问题。

## 实施方案

- 业务编排移到 RagChatStreamService，Controller 只委托。每次订阅独立准备消息与状态；数据库事务只包消息准备/终态写入，不包含模型或检索网络调用。
- 增加生成状态 GENERATING / COMPLETED / FAILED / CANCELLED；兼容旧记录，不把旧 completed=true 自动宣传成模型成功。completed 仅新 COMPLETED 为 true。
- SSE 采用 start / delta / terminal 命名事件及 JSON 数据。正文原样输出，终态有状态和安全错误码/提示；成功必须在保存后发 terminal。断连前已收到内容不能被错误说明替换。
- 完成、错误、主动停止、订阅取消进入同一个终态入口；线程安全冻结已生成前缀，事务内锁行防止后到终态覆盖已保存状态。删除消息后迟到回调不创建新消息。
- 生成过程有有界生命周期与注册表清理。停止入口按 sessionId + messageId 定位资源，先决定终态再通知上游；不能只停页面接收。当前验收为单应用实例，不声称跨节点资源取消；多实例部署需要取消指令送到资源所属节点。
- 读取上游与数据库写入避免阻塞 Reactor 网络事件线程；沿用有界 Reactor 调度能力，不创建自定义无界线程池。
- 历史只加入完整成功的问答对，排除未完成/失败/取消回答及其孤立用户问题。
- 前端要求 terminal 才确认成功；没有终止事件的 EOF 是中断。按请求身份和固定消息 ID 更新，卸载/切换会话释放请求，停止有独立操作。保留部分正文并显示“生成失败/已停止/连接中断”；重载后从持久化状态读取。
- 新字段提供明确 SQL 迁移；不能依赖生产自动建表。快照仍仅沿用已有有限来源预览，不增加完整知识库正文导出。

## 自评审和必须验证的风险

| 风险 | 要求证据 |
|---|---|
| 上游半途失败伪成功 | 基线回归失败证据；新链路保留前缀、FAILED、仅一次 terminal |
| 取消与完成竞争 | 正反序与并发竞争测试，迟到完成不能覆盖停止；上游订阅解除，注册表清零 |
| 保存失败误报成功 | 故障注入；客户端获知当前答案未保存，不发成功状态；不得静默丢异常 |
| 检索前失败、删除会话、无答案/空流 | 全部占位/资源有清楚出口，不复活已删除消息；无答案正常完成与错误分开 |
| SSE 跨网络块及字面转义 | Unicode、实际换行、字面 \\n、多行事件、缺失/重复 terminal、网络中断的真实解析测试 |
| UI 会话串写、停止 | 实际浏览器控制流验证，刷新后的状态与部分正文一致；测试替身只证明协议/故障边界 |
| 正常实际模型回归 | 公开受控问题、小批量；保留真实 usage、正文和来源。无性能收益声明 |

方案是 Agent 自评审，未冒称独立人审。全量后端测试与前端构建必须完成；相关当前依赖 API 先查源码/一手资料。

参考：[Spring MVC 异步请求](https://docs.spring.io/spring-framework/reference/web/webmvc/mvc-ann-async.html)、[Reactor Flux](https://projectreactor.io/docs/core/release/api/reactor/core/publisher/Flux.html)。materialize 可把源信号作为数据处理；doFinally 覆盖取消但在向下游发终止信号后执行，因此不能只靠 doFinally 决定客户端“已保存成功”。

S0–S4 与原指标门保持有效；此修复不替代语音浏览器规模实验或正式新材料质量对照。
