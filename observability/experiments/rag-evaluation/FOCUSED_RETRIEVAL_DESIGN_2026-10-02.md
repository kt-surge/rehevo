# 有限分题召回方案与评审

状态：扩大开发输入及 A 基线已冻结；本设计由同一执行 Agent 自审，允许实施可关闭实验，不批准默认启用。

## 1. 需求与证据

八份官方资料实际上传/复用、54 个实际块、69 条原文事实，65 题中 53 题可回答。所有事实在完整索引中保留。原四份文档的 24 个 UUID、内容、元数据及向量值指纹不变。

真实 HYBRID 初次诊断：候选完整必要证据 52/53，最终上下文 47/53，条件覆盖 84/90。六道遗漏集中于比较和跨文档问题；五道的必要证据存在于候选后部。新资料与问题在看分数前冻结。输入仍为同 Agent 自审、中文问题/英文技术文档开发集，不能称独立 test 或生产收益。

## 2. 候选实现

保留完整原问题的普通 HYBRID 检索，最多再做两个有界辅助检索。辅助查询只取原问题中的自足子句或完整技术标识；不调用 Chat，不读取 Gold、参考答案、文档相关性标签或题号。

优先识别有明确分隔、长度合理、包含技术主体且无指代的子句；对明确比较、无法安全拆句的问题，仅用两个完整标识作为辅助召回词。辅助查询是召回手段，不能替换最终生成的原问题及约束。只有一个主体、指代不清、主题过多或问题过长时保留原检索。

各路沿用现有 20/20 候选及 3:1 RRF。合并时按各查询排名交错、按向量 ID 去重，合并候选仍最多 20，最终块数不超过当前问题的 topK。原问题支路先取，再轮到辅助支路。新模式 `HYBRID_FOCUSED` 显式启用，其他模式和默认不变。

最终文字 Token 使用当前 Spring AI 计数器估算。常规产品调用的新模式预算不超过同次原检索的上下文估算；对照接口额外允许统一预算，A/B 都按相同预算装入完整块、超大块跳过，不截断句子。首轮比较统一 6,000 估算 Token 与原 topK 上限；初次无预算扫描仅为诊断。估算不包含 Prompt/来源标签，也不是供应商收费 Token。

记录每个辅助查询的向量/词法/融合排名，实际向量检索调用数、最终预算及估算量，避免把额外召回藏在分数里。额外检索失败应显式失败；不吞供应商异常并声称成功。没有辅助查询时只做一次原检索。

## 3. 同条件验证

1. 先冻结生产 A 源码；新增可解释 planner、唯一片段选择及预算门的必要回归，全量后端 fresh run。
2. 同一应用、模型、54 个 UUID、Gold、topK、RRF 与 6,000 预算实际采集 A/B；比较必要条件/整题证据覆盖，逐项列出改善与退步。请求级计划及原始响应保留。
3. 额外 Embedding 检索次数与耗时一起列出。先后各一遍仅为诊断，不能推导因果延迟收益。
4. 有收益才冻结策略并准备主题/来源隔离的新 test；不能看 test 后继续调参再称首次盲测。默认切换还需新 test、实际生成及产品路径证据。

## 4. 评审问题与处理

| 质疑 | 处理 | 决定 |
| --- | --- | --- |
| 子问题丢掉否定、版本、上下文 | 原问题保留；只复制原文自足子句，指代和过多主题降级；标识仅辅助检索 | 条件通过，需回归与逐题复核 |
| 三倍召回只是在多放上下文 | 候选仍 20、最终仍原 topK、A/B 同预算；未改索引/模型/重排 | 已限定 |
| 自动按文档均分会拉入无关资料 | 不按文档 ID 分配，只按实际查询的相关排名交错 | 条件通过，需看单主题回归 |
| 三路结果的 RRF 分数不可直接比较 | 使用每路内部排名，不把不同请求的相似度相加 | 已限定 |
| 额外调用与延迟抵消收益 | 最多两条辅助、只比较类问题触发；记录调用数，收益不足撤回 | 待实测 |
| 仅验证开发题即宣传提升 | 新 test 与生成验收仍为后续硬门；本轮仅候选开发诊断 | 已限定 |

## 5. 参考与适配

[微软检索阶段指南](https://learn.microsoft.com/en-us/azure/architecture/ai-ml/guide/rag/rag-information-retrieval)支持把复杂信息需求拆开检索再合并；这里仅实现无需新模型的有限原型，不继承文档中的效果数字。[Qdrant 混合调优指南](https://qdrant.tech/documentation/search-tuning/how-to-tune-hybrid-search/)提示区分候选缺失与排名问题；本次保持 pgvector 和现有 RRF，不引入新向量数据库。

新开发资料为 [Redis XAUTOCLAIM](https://redis.io/docs/latest/commands/xautoclaim/)、[Spring 事务传播](https://docs.spring.io/spring-framework/reference/data-access/transaction/declarative/tx-propagation.html)、[Java 21 CompletableFuture](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/concurrent/CompletableFuture.html)及[ExecutorService](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/concurrent/ExecutorService.html)。它们是被检索的事实来源，不是本项目优化收益依据；HTML 与正文下载、日期/版本和指纹均冻结在开发包。
