# 技术标识正文选择：方案与实验门

## 当前依据

上一轮分题召回的新来源/主题 test 没有收益，因此不默认开启，也不再增加查询数。扩大开发集的 HYBRID 同预算 A 有五道最终证据不完整：四道完整证据已在 20 个候选中，一道仍缺候选。仅按标识命中预留片段的离线投影没有改善；优先重复标题与签名的正文片段投影为 48/53 → 50/53、85/90 → 87/90，没有整题退步。它只证明冻结开发候选上的选择机会，不是实际检索、生成、性能或泛化成绩。

## 候选实现

- 实验模式 `HYBRID_IDENTIFIER`，默认 HYBRID 保持不变。原问题只发一次向量检索和一次已有词法检索，原 RRF 候选及顺序不变。
- 输入仅为原问题、当前候选原文及排名，不读取金标、题号、来源标题、文档 ID 或标注主题。原文块不改、不裁。
- 从最长 512 字问题提取至多 8 个 ASCII 标识；点号限定名称使用末段，注解去掉 @。点号标识优先，其次注解/下划线/大写标识，再按原出现顺序。
- 对每个标识检查 ASCII 单词边界。优先当前候选中出现“独立名称行、随后声明中再次出现同名和左括号”的片段，否则选首次精确命中。这个模式是正文线索，不能保证完整正文、相同语义或正确所属类。
- 最多预留 `min(4, topK/2)` 个不同块；随后按原排名填充，整块超预算跳过。相同 8 块上限和 6,000 估算文字 Token；未显式预算时不超过本次原 HYBRID topK 的估算量。
- 保留原候选、实际最终块、预留标识/UUID/正文线索、实际一次向量搜索和 Token 估算。预留不等于一定装入最终上下文。

## 自审与限制

这是执行 Agent 自审，没有独立人工或第二位 Agent 评审。允许受控实施，不批准默认切换。Java API 中摘要和详情确实分开，参考 [Java 21 CompletableFuture API](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/concurrent/CompletableFuture.html)；[PostgreSQL pg_trgm](https://www.postgresql.org/docs/17/pgtrgm.html) 会忽略非字母数字字符，这说明现有模糊检索不能替代技术标识精确边界，但官方机制本身不证明本项目收益。

风险：同名方法所属类不明、定义横跨块、普通英文或布尔字面值被当标识、构造器或示例被误判为正文、半数预留挤占其他条件、原候选缺失无法修复、纯中文无标识问题保持原选择。上述风险进入真实新材料评测，不添加按题定制规则。

## 实验顺序与通过条件

1. 全量后端 fresh run。冻结候选源码、参数及已有开发输入；先做实际开发集 A/B，比较所有题、条件和成本，不只采集改善题。
2. 在读取新测试来源前冻结策略；新测试材料使用尚未使用的 Java 正则 Matcher、Python heapq/bisect 等官方资料，含单主题、跨资料、默认/否定/参数边界、资料不足问题。这个取样不是独立执行者盲测或随机用户抽样；明确同 Agent 知道策略。
3. 金标在首次 test 检索前冻结并自审，来源/主题/原文指纹与开发集和已暴露 test 不重叠。任何 test 评分后不得改策略或金标；当前旧 26 题只可作为已暴露回归。
4. 相同模型、实际 UUID、候选20/块数8/文字预算6000；关闭改写和重排，保留全部失败、超时及资料不足分母。真实接口检查知识库范围、预算和追踪信息。
5. 必须有新材料必要证据改善、无关键错误/明显退步及可接受代价，才能进入生成实验；默认启用另需生成忠实度/完整性/引用/拒答与实际产品入口验收。失败则保留诊断和撤回决定。

不得以离线投影、方法签名命中或单元替身时间填补真实语音、生成和产品路径验收。
