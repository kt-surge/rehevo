# RAG 引用评审 v2：程序守卫完成，语义质量仍 HOLD

## 结论

本轮解决了评测程序制造引用、错误来源引文、任务编号漂移和全文支持受错误引用影响的问题。使用 8 个公开校准样例、上一轮 6 组 A/B 的 12 份原回答；没有重新生成答案，也没有改变应用默认配置。该评测仍不能输出可采用的忠实度、引用支持率或简历质量数字。

全部 S0–S4 目标继续 active。8 次应用 Flash/27B 对照已在 r9 用完；本轮为持续目标授权内的公开 RAG 评审，未追加应用跨模型对照。

## 实现与验证

| 环节 | 实际实现 | 验证边界 |
|---|---|---|
| 实际引用提取 | remark-parse AST；原句/引用 Unicode 位置；排除代码、转义及已有链接，保留未知编号与重复出现 | 18 个离线样例通过；不推断跨段落引用 |
| 原文分段 | 仅看原回答；每段逐字拼接必须等于原文，位置吻合，否则拒绝 | 不保证模型分类正确或每段只有一个原子事实 |
| 结构与引文 | strict JSON Schema 固定字段/编号；程序预先给来源原句和回答片段编号，裁判仅选择 quoteId，程序回取原文 | 不能靠 JSON 结构保证语义真假；错误来源选择仍须校准 |
| 全文与引用支持 | 独立请求；全文请求去掉实际引用标记，保留原句及所有上下文；引用请求只含各自固定来源 | 校准错误引用时全文仍受支持，引用单独失败；多来源的集体充分性与删除来源后的必要性未测 |
| 覆盖与拒答 | 独立评审必要事实和未知要求；回答已知部分、拒绝未知生产参数分别计量 | Spring 默认设置/回滚的必要事实限于问题要求，不要求复述源段中无关的超时/读写属性 |

21 项 Python 守卫/隔离测试通过，加 18 项实际 AST 样例。应用代码本轮未改；不重复把上一轮 385 项应用回归记成本轮新增测试。

8 个校准样例包括无引用、无关来源、冗余来源、资料缺失说明、部分回答加拒答、错误快照、编造重试秒数和错误代理条件。最后一项原请求读取超时无响应，单独的一次恢复预检已记录；原失败和未知用量未覆盖。

## 开发复测与逐文复查

- 12 份原回答全部完成程序守卫及分开的语义评审；普通臂实际引用、引用边均为 **0**，未再被裁判补成 E 编号。
- 原始裁判统计看起来可得到很高的支持/覆盖比例，但逐文自审否定其采用资格：两份正确拒答中的 NOACK/CLAIM 背景事实被整段归为 missing_information，漏出了事实评审；四份包含 `PEL（Pending Entries List）` 的回答被全文支持判 true，而该定义并不在本轮供给片段中。
- 源文自审记录为 **6 处具体问题**，不是总体错误率。原子事实拆分、必要条件和术语定义不能由整段概括支持代替。
- E3 的 Spring 回滚片段本身包含默认传播设置，不能单凭 E3 编号判它与传播断言无关。校准的真正无关片段采用只讲 PostgreSQL 隔离的 E2；重复来源的必要性与来源支持精度也须分开。
- `reviewed-summary.json` 与 `semantic-audit.json` 给出最终 HOLD；复查前 `pre-audit-summary.json` 原始计数保留，不转写为可采用质量百分比。

未曝光资料、独立人审、跨模型裁判、RAGAS 正式效果、真实检索、浏览器延迟、版本元数据完整性均未在本轮完成。
