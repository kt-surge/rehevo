# 引用评审协议 v2（已实现程序守卫，语义采用门未通过）

## v1 不能采用的原因

6 组 12 次真实生成、12 次结构化裁判已保留。匿名去掉 arm 名称不能保证裁判可靠：裁判把普通回答没有的引用补成了 E 编号，26 个断言出现这种分配；把部分“资料未提供”的说明计作不忠实；把正确拒绝生产参数的答案因含背景说明判为没有拒答；引用支持以整组来源判断，掩盖单条无关引用。

这些不是 JSON 解析失败。原始百分比必须保留用于复查，但不得当作采用门或简历数据。裁判与生成均为 Flash，且规则在首批 4 条回答可见后编写，不能称为预注册或独立盲审。

## v2 分解

1. **确定性提取引用**：先由 Markdown 解析器提取实际正文中的编号、原句和位置。代码、转义、已有链接及未知编号独立处理。裁判不能生成 citationIds；每个评审任务的原句和证据 ID 在调用前冻结。
2. **原子事实提取**：仅看回答拆事实，保存原文范围、条件、否定和版本。缺失信息的说明与肯定技术事实分开。不允许提取器添加回答没有的文本；子串/位置不吻合就保留失败，不自动修复通过。
3. **上下文支持**：每个断言对本轮完整上下文评审，要求直接支持的原句；多跳依赖需显式列出。答案正确但证据未给定义的常识扩展仍不算有依据。
4. **逐条引用支持**：对确定性提取的每个断言－来源边分别判断相关性和支持，不能用“所有来源并起来支持”掩盖无关引用。同时评估断言有无足够引用，避免只引用少量安全事实刷精度。
5. **必要事实覆盖**：独立对冻结的需求/条件/替代证据组检查，保存回答原文，不能只复述 Gold。没回答关键事实与给出无依据事实分别统计。对包含多个必要条件的一项要求必须全满足。
6. **拒答**：以问题中可回答/不可回答的要求为单位标记。拒绝一个未知生产参数但附上证据范围说明，属于拒答；对混合问题保留已知部分，不算整个问题拒答。拒答和缺失说明不直接进入事实忠实度分母。

## 校准与采用

- 固定负例包含：无引用回答、编号存在但无关来源、多来源中的冗余编号、未提供定义的常识、缺失说明、条件遗漏和版本丢失。
- 引用提取与范围校验不得出现制造引用；原句、来源引文、必要事实集合不合法时不能产出通过分数。
- Agent 自审与人审状态分开。先复查开发集误判，再冻结裁判/规则，用策略修改后未曝光的新资料验证既定 S3 门槛；v1 开发结果不得升级为正式指标。
- 沿用目标中的忠实度 ≥0.95、必要事实覆盖 ≥0.90、引用支持 ≥0.95、可回答误拒答 ≤5%、不可回答拒答召回 ≥90% 和成本/流式门，不改小目标。
