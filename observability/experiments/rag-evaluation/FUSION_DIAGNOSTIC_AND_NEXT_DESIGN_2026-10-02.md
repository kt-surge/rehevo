# RAG 融合诊断与下一轮实现设计

状态：源码核对、官方资料复核和离线开发诊断完成；本设计由执行 Agent 自审。**当前没有新增检索收益，不修改默认策略。**

## 1. 当前链路与具体缺口

`KnowledgeBaseQueryService` 根据问题长度决定最终片段数，原问题/可选改写送入 `HybridRetrievalService`。后者先查向量候选，再查字符三元组候选，以 `weight/(k+rank)` 融合并截断候选，随后取最终上下文；相邻块和重排仅在指定模式启用。同步及流式生成使用选中的实际片段。

当前实际实验配置：向量/词法各 20，融合 20，k=60，向量权重 3、词法 1，长问题最终 8。词法 SQL 是 PostgreSQL `pg_trgm` 的 `query <<-> content`，**不是 BM25**。跨文档失败 `primary-dev-cross-02` 的另一必要事实进入融合候选第 13 位，在最终 8 块处丢失。

## 2. 本次离线诊断

复用冻结的真实向量和词法排名，先精确复现当前 34 题融合候选 ID/顺序。比较 4 个 k 与 6 组权重，共 24 组；包含各单路候选排序投影。每题最多保留原上下文块数，片段 Token 估算不超过该题原预算，超大块跳过后继续装入。

结果：最佳仍 **25/26 必要证据完整覆盖、43/44 必要条件覆盖**，未修复跨文档缺口。多个纯向量投影与偏向向量配置达到相同覆盖；相同分数不证明某一策略更快或更省真实模型费用。没有新增召回、真实 API、生成或延迟对照。

决定：停止继续围绕这个小开发集拧融合权重；保持默认 HYBRID。下一轮需要增加能辨别策略的材料及针对复合问题的召回。24 块语料中选 20 块仍有明显覆盖上限效应。

原始数据：[全部参数及逐题结果](runs/fusion-offline-dev-20261002-r1/comparison.json)、[75 个成果指纹](runs/fusion-offline-dev-20261002-r1/artifacts.sha256.json)。首批目录因工具要求逐题耗时而中断，未形成实验结论；r1 明确标记耗时继承原采集，省略投影的汇总延迟，未填造新性能数据。

## 4. 下一轮实施顺序与通过条件

### A. 扩大开发材料，先冻结输入

准备更多官方技术资料和相关干扰材料，使候选上限不再覆盖大半语料。增加中文/英文交叉、自然语言、技术标识、相近命令、否定条件、跨文档多条件及资料不足问题。题目的条件、例外、替代来源和出处区间沿用事实金标工具；同 Agent 自审继续显式标记。

新的最终测试按来源/主题隔离，策略冻结后首次执行；同一文章换措辞不视为独立新 test。先确定开发材料与问题清单，再查看策略结果，不按哪种策略胜出来挑题。

### B. 比较有限复合召回

1. 保留当前 HYBRID 作 A；新增可关闭的复合召回模式作 B。原问题始终保留；最多 2–3 个子查询，不做无限 Agent 循环。
2. 记录每个子查询与来源支路、调用数、候选和最终证据。子查询不能读取 Gold 事实、相关 Chunk ID、答案或人工题号。
3. 在相同最终片段数和 Token 预算内合并；单主题结果占满时比较有依据的主题覆盖选择，避免简单按文档平均分配导致无关材料进入上下文。
4. 当前开发集只能用于诊断和回归；扩大材料后冻结策略，再运行新 test。必要证据覆盖提高且单主题/资料不足切片无明显退步，才进入真实生成验收。

### C. 比较技术标识召回

先保存当前三元组对技术键、注解、完整类名和版本符号的真实排名；确认缺口后再加精确标识支路或适合材料语言的词项检索。原标识、大小写、符号和解析后文本分别保存。涉及标识的精确匹配应带边界，不能把 `foo` 命中 `foobar` 当作正确证据；新支路不可跨用户选定知识库。

通过条件是必要证据/正确标识排名改善，而非关键词命中率自证。额外索引、维护成本和读延迟一起比较；暂不引入 Elasticsearch、外部向量库或新模型。

### D. 生成验收独立推进

恢复同模型额度后，固定实际上下文，分别检查断言忠实度、必要事实覆盖、引用支持与拒答。上下文里存在正确材料不等于模型用对了材料；真实供应商 Token、首输出和完整输出时间单独采集。没有生成数据时不补写 RAGAS 成绩。

## 5. 本次评审结论

条件通过：先扩材料和失败切片，再做有限复合召回与技术标识支路；当前融合权重扫描及相邻块/重排负结果保留。默认策略仍不变。阶段必须交付真实 API 对照、逐题原始证据及未暴露测试，离线投影不能代替目标要求的有益 RAG 改进。
