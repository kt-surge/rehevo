# G1 引用链路：实现、实测与保留决定

## 当前决定

已实现本轮证据编号、编号存在性校验、来源快照、正文引用跳转与有限原文预览。真实浏览器完成两轮受控问答；不同轮次的 E 编号确实对应不同供给顺序，并能定位本轮来源。生成引用提示词仍为默认 **OFF**，未宣称忠实度或正式引用质量提升。

结果目录：`runs/citation-chain-20261005-r1/`。完整 S0–S4 目标继续有效。

封存 622 个文件，SHA-256 初检无差异，现有密钥精确值扫描为 0。隔离应用已恢复默认关闭引用提示词并健康 UP；受控会话、实验页与前端进程已清理。原四份公开知识库的 24 个向量指纹不变，隔离库仍为 15 份文档 / 123 个向量 / 0 个 RAG 会话 / 0 个语音会话。

## 已实现与验证

- `RagEvidenceContext` 按本轮实际供给顺序编号，不借用检索分数或名次。同步、生成评测和会话流式路径共享映射；检索 trace 不赋予生成引用编号。
- `RagCitationValidator` 单独报告 DISABLED / NO_REFERENCES / REFERENCES_KNOWN / UNKNOWN_REFERENCES。忽略代码、转义和显式链接，未知编号不删改回答。不把编号存在性命名为忠实度。
- E 编号保存到证据快照；旧快照缺字段仍为空。前端正文引用只绑定当前消息的来源，刷新从快照加载；来源区改为“检索来源”，不再宣称所有候选都被回答使用。
- 实测发现两个 UI 问题并修复：虚拟列表重绘使展开区恢复折叠；自动滚到底部盖过引用定位。改为保存展开状态，仅在生成期间自动跟随。首次失败截图也保留。
- 最终预览仍限制每条 **240 字符以内**，用问题中的技术标识截取最多两段原文，不改变生成正文、排序或召回。第二轮 E1 预览实际显示 NOACK 不加入 PEL 与 CLAIM 例外；E6 显示读取时确认行为。
- 最后全量后端重新执行：**79 个测试类、385 项，0 失败/错误/跳过**。前端最终 `pnpm run build` 成功；7 个实际 Markdown AST 场景通过，覆盖未知编号、相邻引用、代码、转义、现有链接和跨消息作用域。

## 真实生成对照

6 个已曝光开发场景，含多条件、跨文档、部分可回答和生产参数不可回答。精确公开来源事实片段、问题、顺序冻结；3 AB / 3 BA，以同一 Flash、温度 0.2、关闭思考、480 completion tokens 上限运行 12 次。

实际调用使用应用的提示词构造器及 `LlmProviderRegistry.getChatClientOrDefault`；属于固定上下文生成组件实验，不含实时检索、浏览器延迟或用户简历。Prompt 留存为服务供给文本，不宣称抓取 HTTP 原始请求。StringTemplate 同时把两臂的 LF 转为 CRLF，原始供给 Prompt 保存，内容及顺序的核对明确记录这一共同转换。

| 指标 | 普通上下文 | 编号上下文＋引用规则 |
|---|---:|---:|
| 成功生成 | 6 | 6 |
| 回答实际含 E 编号 | 0 | 5 |

| 输出 Token | 747 | 642 |

编号方案在此小样本总 Token 增加 **6.22%**；不能把输出变短当作用户体验或忠实度提升。存在跨文档过多引用、定义未在摘要出现仍做解释，以及版本信息没送入上下文的问题。开发者核对是源码/来源作者自审，不是人审或正式盲测。

## 裁判失效与禁止采用的数据

12 次固定结构化 Flash 裁判均返回可解析结果，用量完整，但语义校准没有通过：

- **26 个断言**被分配了原回答没有的引用；普通臂实际没有任何 E 编号。
- 对“资料没提供”的元说明分类不一致，部分被计作不忠实。
- 两个明确回答不能确定生产配置的答案，因附带证据范围说明被错误归为没有整段拒答。
- 用一组来源联合判断支持，掩盖其中个别无关引用；原句引文还存在省略、拼接和非逐字引用。

原始裁判百分比保留在 `preflight-summary.json`，**不作为采用指标或简历数据**。`judge-protocol-audit.json` 明确否定其采用资格，并纠正原计划里“规则在结果查看前冻结”的不准确字段：规则在首批 4 条回答已可见后编写，匿名 arm 也不代表独立盲审。后续协议见 `CITATION_JUDGE_PROTOCOL_V2_2026-10-05.md`，已实现程序守卫与开发诊断，语义门仍未通过。更新见 `CITATION_JUDGE_V2_RESULTS_2026-10-05.md`。

评估口径参考 [Ragas 指标定义](https://docs.ragas.io/en/latest/concepts/metrics/available_metrics/) 与 [ALCE 原项目](https://github.com/princeton-nlp/ALCE)：检索、事实正确性和引用质量需要各自的证据。此实验的自定义裁判不称为 RAGAS 得分。

## 实际浏览器

- 第一轮：正常 RAG 检索、SSE、会话落库、自动重载；8 个来源，两条事实引用 E2。点击展开的初版缺陷保留并修复。
- 第二轮：同一受控会话，当前轮引用 E1/E6，E1 对应第一轮 E2 的同一文档片段。快照中的编号跟随各自轮次，不被当前排序覆盖。预览每条 ≤240 字符；最终点击后 E1 卡片在视口内并保持展开，原文包含 CLAIM 例外。
- 这些是两次实际产品问答与 UI 正确性证据，**不是配对延迟实验、压力测试、生产流量或正式生成质量数据**。
- 首次创建会话被实验端口的 CORS 拒绝，0 模型调用。运行器只增加可选的单个 localhost 来源参数，生产配置不变。
- 完整片段新增到响应/快照的方案被自动审批拒绝，理由是扩大私有知识库内容向浏览器的暴露范围。该补丁未执行；采用评审建议的有限预览替代，不增加完整正文响应字段。

## 后续持续目标

先实现确定性引用/原句提取和逐条断言－证据评审，校准裁判，再以未曝光新资料执行 S3 正式门；补齐流式取消/错误保存状态。继续 S2 实际浏览器 ≥100/臂、≥3 时间窗语音与应用 ASR，及 S4 岗位出题－评估－训练－文字定向复测和故障边界。尚不能把本轮工程链路写成已验证的生成质量提升。
