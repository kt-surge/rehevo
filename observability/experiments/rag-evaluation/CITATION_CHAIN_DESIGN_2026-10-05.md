# G1：回答引用与证据快照

## 需求与采用标准

让用户能从回答的 `[E1]` 找到本轮实际传给模型的片段，刷新会话后仍对应同一个文档、文件哈希和片段。不能把“检索到了”“编号存在”说成“断言正确”。保持 S0–S4 原目标与后续正式新资料验收。

## 技术依据

- Ragas 的 Faithfulness 比较回答断言与实际上下文；Factual Correctness 比较回答与参考事实。两者分开：https://docs.ragas.io/en/latest/concepts/metrics/available_metrics/ 。
- ALCE 分别评估正确性和引用质量，引用编号存在不是引用支持率：https://github.com/princeton-nlp/ALCE 。

## 实现与自评审

1. 增加默认关闭的 `app.ai.rag.citation.enabled`。开关开启时，按实际上下文的供给顺序分配 E1、E2；不使用检索分数/名次作为编号，不变更召回、正文、排序、截断或拒答门。
2. 共享上下文构造器生成编号和正文。编号与同步/评测/流式响应中的来源 ID 共享；检索 trace 不冒充已喂给模型的证据。没有真实来源元数据时不编造标题、版本。
3. 提示词只要求可核实的事实后附有效编号，部分答案仍保留，无依据部分仍说明缺失，不强迫给拒答附引用。
4. 纯语法校验只返回编号状态、已出现编号、未知编号。没有引用、未编号的历史和未知引用都不包装成忠实度通过。报告不会删改模型原文、触发额外模型调用或自动修复。
5. 证据 ID 随历史快照持久化。旧快照缺字段保持空，不按当前顺序事后补编号。前端仅把匹配本轮 ID 的正文引用绑定到对应来源；代码/现有链接内不转换。未知编号保持原文并提示无法匹配。
6. 前端来源区用“检索来源”，不宣称全部片段实际被回答使用。跳转主动展开来源区，避免链接落到折叠内容。

边界：编号规则为 `[E数字]`；来源绑定不验证该句得到支持。首版不做在线 NLI 裁判，避免在每轮链路引入延迟和费用。断言支持、必要事实覆盖在离线实验中评估。

## 实验

- 先冻结原始代码与提示词，保留所有失败。Windows 长路径首次冻结失败，修复路径读写后继续，失败记录保留。
- 正确性：供给顺序与正文等价；历史重载；未知/空引用；旧快照；代码/链接保持原样；同步与流式同一映射。运行全部后端回归与前端构建。
- 真实小批预检：固定公开技术上下文与问题，A 普通上下文、B 编号上下文＋引用约束；其余模型、参数、顺序、正文相同。记录实际请求、usage、回答、引用存在、断言支持与必要事实。复用已曝光开发资料只能诊断，不能充当正式新测试。
- 小样本、开发者自审、离线投影不作为生产指标。默认 OFF，直到既定忠实度、必要事实、引用支持和拒答门在新资料实测通过。
- 不扩展已经使用完的“8 次应用语音跨模型对照”授权；本项使用原目标已授权的公开技术资料 RAG 对照和现有 Flash。

## 仍需后续验收

固定裁判、断言－证据配对与误判复查；新资料正式实验；流式错误/取消保存部分答案与完成状态；≥100/臂实际浏览器语音、应用 ASR 与 S4 完整业务链路。
