# 封闭输入评估：工具访问单因素诊断与评审

## 当前实现与假设

文字 InterviewSessionService、语音 VoiceInterviewEvaluationService、EvaluationBenchmarkService 获取默认含 SkillsTool 的客户端。评分输入已经包含当前问答、文字题 guide 与岗位参考，工具读取并非评分所需。前轮真实模型可输出不存在的题目与回答；未证明工具调用是其唯一原因。本轮检验关闭工具是否减少额外调用，并改善当前受控输入的内容归属。

已有 Registry.getChatClientOrDefault(provider, ToolAccess.NONE) 使用相同 provider/model 配置，不发送工具定义，不加入工具或全局记忆 advisor，保留 SafeGuard。现有真实 loopback HTTP 测试验证默认客户端含工具、NONE 不含工具。复用这条路径，不新增模型路由。

## 单因素范围

实验 A/B 同一当前评估实现、严格 JSON/Schema 中央重试、Prompt、岗位参考、公开问答及实际有界执行器；唯一参数为 DEFAULT/NONE 工具访问。原八次跨模型对照不复用，模型仍为现有默认 Flash。本轮不同时修改评分提示、题号/引用规则、截止机制或 Native JSON。

先跑一场 NONE 开发预检，输入取自上一轮已曝光的受控记录，一题已回答、一题未回答。通过后才制定当前源码冻结的随机配对开发实验；预检不是正式质量数据或无偏效果估计。每场最多三次 invoker 操作，中央每次最多两次结构尝试，实际 SDK 操作/Token 和失败全部记录；工具调用与底层网络请求数不能由该上限推造。

## 验收

- 原始题号为 [0,1]，不得出现其他题目、把岗位参考说成候选人回答。
- 一题已回答应有引用原文、SCORED；未回答题保持 UNANSWERED，不形成能力结论。
- 训练任务只关联有效评分的 index 0，动作与真实事务/消息缺口一致。
- 严格 JSON/Schema、问题归属、引用、任务来源均经过原始输出与报告复查；仅结构成功或引用字符串匹配不足以证明技术判断正确。
- 观察调用/用量，不用一次耗时或少量成功声称生产指标。若再虚构输入或格式失败，停止扩大批量，保留负结果并检查下一处实际瓶颈。

## 评审与生产采用边界

执行代理审查：NONE 路径已存在、相同模型设置、SafeGuard 保留；封闭输入无需工具补充事实。无新增依赖或外部数据范围。模型仍可能幻觉或漏引，全部既有校验保持。真实预检通过后，先将三个评分入口改用 NONE，运行全量后端及实际文字/语音产品复验；稳定能力标识与原 S0–S4 质量、语音浏览器及 RAG 门仍需单独完成。
