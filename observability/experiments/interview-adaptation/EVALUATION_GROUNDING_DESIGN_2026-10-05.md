# 评估输入与来源绑定修复方案及评审

## 现场问题与边界

training-history-product-20261005-r1 的原文讨论 Redis Stream / Spring 事务，反馈却描述线程池，且任务 questionIndexes=[1] 指向未回答题。负结果已封存。评分内容偏移的具体原因尚未证明；以下源码缺陷已确认，不把它们直接说成现场幻觉的唯一原因。

1. 当前按模型数组位置合并，未核对其 questionIndex；单题重试也直接取首项。
2. 输入写问题 1 / 汇总 Q1，API 存 questionIndex=0，没有明确两种口径。
3. 伪证据在最终展示时过滤，过滤后仍可 SCORED，并进入汇总和训练任务。
4. 汇总只有截断的题目与反馈，没有原回答、实际状态及经过校验的证据；任务只校验题号存在，不校验已回答/成功评估。

## 实现

- Prompt 明确原始 questionIndex 为唯一关联值，显示序号另列。合并及单题重试按原始值关联；重复、缺失、越界项不猜测、不按位置补配。
- 评分须至少有一条可在当前回答逐字找到的短句。先校验、再汇总；没有证据的已回答题标记 EVALUATION_FAILED，可按原有预算和单题重试上限重试。未回答题保持 UNANSWERED。原文证据存在只能证明引用归属，不能证明技术判断正确，效果仍需人工复查。
- 汇总输入完整保留本次已回答题、实际索引、状态、评分依据、已验证引用及缺失点。未回答题不可触发训练任务。无可信评分则不调用总结模型，也不采用无来源的批次综合结论。
- 模型任务只允许关联有证据的已评分题；不自动把显示序号改成索引。已有评分 guide 的能力点必须与其一致；否则降级为从有效逐题结果构建的可追溯任务。稳定跨场能力 ID 与语音 guide 仍需下一阶段设计，不能用模糊名称匹配抬高复测覆盖。
- 保留默认模型、统一 StructuredOutputInvoker 的结构化重试、现有评分分数区间、报告 DTO 和事务边界。本批不增加新的模型切换或大规模质量评测。

## 评审

执行代理逐项审查：修复不依赖模型遵守题号约束，不做猜测式偏移；证据门在训练前执行；任务无来源时明确失败，避免捏造训练。风险：原模型可能漏引导致评分覆盖下降，因此必须同时报告评估覆盖和证据覆盖，不能只报告已接受项的质量。原文引用并非语义正确性证明，正式质量门保持 HOLD。

## 对照与验收

先在旧源码运行同一回归集，冻结失败 XML/源码；再实施候选、跑全量后端和同一回归集。检查乱序/稀疏 ID、重复/错 ID、伪引用/空引用、未回答任务、能力不匹配、单题重试错位及实际汇总输入。

真实预检仅使用既有默认 Flash、公开受控问答，不含真实简历/JD。用实验类捕获供给给 StructuredOutputInvoker 的完整提示与解析结果；不保存凭据/HTTP 授权头。单次固定输入、原有有界重试、保留用量与失败；这属于诊断，不冒充随机配对的效果结论。若再失败，停止扩大批量，审查输入/模型输出。
