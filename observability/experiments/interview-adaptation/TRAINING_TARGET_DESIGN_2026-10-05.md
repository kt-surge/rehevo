# 训练任务到定向题：方案与评审

## 当前链路与实际缺陷

getRecentTrainingTasks 已读取同岗位/简历范围的文字和语音任务。InterviewQuestionService 仅传 competency/priority/reason，没有 action/completionCriteria；InterviewPlanService 依赖生成能力点显示名精确匹配，模型更换名称就失去关联。最新正常评分预检有事务/ACK 与代理训练动作，但尚未完成实际文字复测。

## 本轮实现

共享确定性选择器，过滤 null/空任务、按优先级选最多三个去重能力重点。为选中任务定义生成稳定训练目标 ID（能力描述、练习动作、验收标准决定；优先级、原因、旧题号不改变 ID）。这是训练目标定义标识，不宣称建立通用岗位能力分类体系。

出题传目标 ID、能力定义、动作、完成标准与待复核原因；明确不是候选人的事实，不要求背诵旧理由。结构化题目返回 trainingTargetIds，每个主问题至多关联一个本次目标，未知 ID、多个 ID 不计关联。Guide 持久化目标关联，追问继承但不进入主问题覆盖统计。

计划保留每个训练目标的定义、优先级及实际主问题索引，以便回查。覆盖分子为被主问题关联的不同目标数，不能因多个题名或追问重复增加。历史无 ID 题单仅保留原精确名称兼容；有未知 ID 时不通过名称兜底制造覆盖。前端将“实际复测”改为“已安排训练目标题”，不把准备阶段的安排说成答题后的效果。

## 调研与评审

[1EdTech CASE 实施指南](https://www.imsglobal.org/spec/CASE/v1p1/impl) 将标识与显示文本分开，供不同系统关联同一能力；此处借鉴关系设计，不引入标准服务/全岗位 taxonomy。[Spring AI 输出转换官方文档](https://docs.spring.io/spring-ai/reference/api/structured-output/converters.html) 的结构化格式仍需应用端校验。本项目保留中央严格 Schema、预算和来源保护，目标关联名单在服务端验证。

不增加模型调用或依赖，不用模糊字符串/语义相似度把旧结果变漂亮。ID 正确只证明模型声明的安排关系；问句是否考查动作和完成标准必须单独技术复查。保留并暴露未关联目标，无法确定时不标记已掌握。

## 对照与验收

先冻结当前 Plan/Question 源码与模板。原 Plan 行为在相同新字段夹具下验证：名称变化、多个显示名对应一个目标、未知 ID 冒领及仅追问关联。基线只增加未使用的数据字段/兼容构造器供测试装配，明确不是 Git HEAD。候选至少完整后端测试和前端 build。

真实模型先一份开发预检，只用已曝光的公开受控训练任务、同默认 Flash/Skill、无真实简历/JD。不与此前八次跨模型授权重复。检查真实问句是否考查事务代理、提交/ACK 与幂等性，Rubric 是否匹配，未知目标/未提供事实不得虚构；不合格则停止扩大。通过后继续冻结同输入的开发 A/B 与实际文字答题→评分→训练/复测产品流程。

最终 S4 仍要求真实产品闭环与质量门；本轮零模型单测、关联率、结构成功均不替代正式学习效果或语音/RAG 门。
