## 1. 同用例对照

| 场景 | A：原实际源码 | B：执行权候选 | 实际收益 |
| --- | --- | --- | --- |
| 第一消费者计算中收到同版本第二通知 | 外部替身调用 2 次 | 调用 1 次，两条通知均处理完成 | 有效租约期间重复通知不重复计算 |

## 2. 实现和评审

- 按父文档→任务行锁定认领，数据库保存 owner、递增 fence、有效租约与尝试次数；认领后才做外部计算。
- 受 Spring 管理的专用调度器续约；已过期、失权或非当前 generation 不能续命。失败或续约丢失使本地许可失效，后续批次与提升再次检查。
- 提升在获得数据库锁后读取 `clock_timestamp()`，核验执行凭据；正式索引、父文档完成与任务完成原子提交。旧失败同样被围栏拒绝。
- 每个接受请求默认最多 4 次认领；恢复通知重建不重置预算。可延后、失败、跳过及完成分别计数，避免将延后重试记为已成功重新入队。
- durable 开启时拒绝无正文接受及无执行凭据状态写入；正文和切块配置沿用已接受快照。

评审结论：保留上述核心修复；默认开启条件仍未满足。Provider/model/dimensions 的恢复快照边界、进程在外部计算中退出、心跳数据库故障、受控负载、终态保留和批量退避继续推进。

## 3. 七项新增协议门

| 检查 | 观察 |
| --- | --- |
| 实际调度心跳 | 租约延长、有效期间第二认领被拒；停止后受控过期可认领，旧者续约被拒 |
| 持久化预算 | 7 条 retryCount=0 通知仅触发 4 次替身计算；次数在外部调用前落库，最终 FAILED |
| 无围栏入口 | 无正文 begin、无凭据 PROCESSING/FAILED 写入均被拒 |
| 旧失败 | 当前执行完成前后，旧失败均不能改状态 |
| 实际锁等待跨过租约 | 数据库观察到 Lock 等待；释放后过期提升被拒，正式及临时向量均为零 |
| 本地失权 | 数据库租约仍有效时，本地许可撤销也阻止提升 |
| 迁移 | 未完成阻断、终态兼容、重复前向、ACTIVE 阻断回滚、终态撤字段；仅影子 schema 回滚 |

四次是“执行权认领”预算；SDK 重试、分块批次和供应商 HTTP 次数不受该数字直接约束。此处失败计算使用替身，不能写成已减少真实付费请求。

## 4. 实际应用重启与核心入口

独立实验 Redis 暂时拒绝 XADD。真实上传仍接受父文档和正文快照，状态 PENDING、持久化执行次数 0、通知 0。停止旧应用，确认旧进程缺失且端口无监听，恢复原 XADD 权限后启动不同 PID 的应用。

实际定时扫描自动投递原 generation，真实 1024 维 Embedding 完成；实验没有调用 `recoverOnce`。该请求及 HTTP 重新向量化形成的下一请求分别认领一次；检索仅返回下一请求的正式向量，文件下载字节一致。删除实验文档后父文档、任务及向量清空，S3 SDK 验证对象 HEAD=404 且 bucket HEAD=200，原四篇 24 块索引保持一致。

第一次紧接工具句柄退出的端口检查遇到应用仍在关闭，验收拒绝启动新实例，原 Redis 权限仍优先恢复。后续脚本遇到 Windows 默认 GBK 读取 UTF-8 JSON 失败及本地连接超时，修正编码并以操作系统监听和进程记录共同确认；原失败检查、初始 helper 及版本差异保留。没有据此重建请求或重跑接受阶段。

这验证“已接受但尚未执行”的跨进程恢复；尚未验证进程在供应商计算中退出的未知结果，也没有测量生产恢复 SLA。
