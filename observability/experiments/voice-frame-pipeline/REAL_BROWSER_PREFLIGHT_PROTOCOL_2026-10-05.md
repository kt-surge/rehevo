# 完整语音浏览器预检：冻结协议与自审

## 目的与边界

真实 React 页 → 实际 Spring Boot WebSocket handler → qwen3.8-flash → 同模型 3.1 TTS → 浏览器输出流。A：现有整句 WAV 与旧逐段播放；B：同句 PCM 帧流与连续排程。二者是一个预先声明的组合改动；TTS 组件归因已有独立单因素证据。输入使用受控字幕替代麦克风，提交后链路真实，指标不含 ASR/用户说话结束检测，不称真人语音体验。

先逐组各一轮正常和一轮取消，验证建连、终态、实际模型/音频/用量、客户端计时和清理。不重试或丢弃失败。修正原因后另建预检子目录，旧数据保留。预检不得并入正式约100次/组、三窗采集。后续正式协议须在首批正式调用前冻结。

## 共同配置和采集

- 同一 checkout、SDK、数据库、Redis、模型、提示词、120字符输出预算、三并发 TTS、超时与输入脚本；无真实简历/JD。相同 Java 岗位、难度、阶段配置，记录实际创建请求及开场文本。
- 两个仅 loopback 应用端口 18080/18081；前端分别关闭/开启连续播放，其余配置共用。关闭开场预热；实际开场请求/缓存命中单列，不计入回答起播样本。
- 两组都加载仅实验 classpath/profile 的 SDK 原始数值观察器；正式产品源码无反射。保存逐 synthesizer 输入 SHA/模式、实际 usage、SDK 关闭与取消方法计时。最终累计事件按 requestId 去重；无 usage 明确 unknown，不补零。
- 受控 loopback 中继只转发实际接口和 WS 消息，注入公开字幕；保存输入、实际输出、逐音频、出站顺序、客户端报告和诊断。转发真实音频后再排入证据写队列。中继和观察器存在采集开销，两组同实现；报告该边界，不把本地实验称生产压测。
- 首有效回复起播以客户端单调时钟为准，两组同用有效 output_pcm；fallback scheduled_pcm 单列，不能混算。首包、排程、实际观察输出与片段时间线间隙分开记录。无占位话术作为回复起点。
- 待控制接口观察到已输出后才点停止；分别记录客户端全部 Source 清理、服务端取消确认、SDK 本地关闭、后续迟到输出。硬件停声/远端关闭确认未测则明确未测。
- 源码/SDK/配置白名单/输入在调用前冻结；实际 Token 和失败保存；退出时关闭实验页、确认资源清理，保护已封存 r2/r3/r4。

## 已定位的接线问题

原服务写死 ws://localhost:8080；在本机端口更换及反向代理下不成立。先冻结旧源码，改为相对 WS 路径；客户端以 API origin 解析 ws/wss，Vite 转发 /ws。两组共用修复，不能把连接修复混算为帧流延迟收益。

## 自审

同一 Agent 自审，无第二位 Agent 或人工审批。通过进入少量预检，默认新协议仍关闭。实际模型输出存在随机差异，须保存终稿/合成内容和输出长度；正式实验随机交替、分层报告，不用顺序两批代表 A/B 因果。前台/后台或暂停带来的不同输出时钟口径必须显式分层。

需预检决定：ASR 新额度模型的应用接线、120字符预算下最终 LLM usage 是否可取得、中继是否完整保存终态和帧、B 的有限队列是否欠载。任何问题先定位再设计正式采集，不能拿未完成链路的组件改善替代完整体验门。
