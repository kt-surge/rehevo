# 连续音频排程与真实浏览器故障复验

## 本轮交付

新 PCM 帧解码器严格校验格式、轮次、句序、帧序与句末。WAV 解码器识别 RIFF/fmt/data 与合法附加块，不再固定跳过 44 字节。

`VoiceAudioScheduler` 把当前及未来片段提前放到同一 AudioContext 时间线：下一片段起点接上一片段终点，`onended` 只释放资源。默认起步余量 12ms，最多 30 秒待播和 128 个 Source；满载明确失败。取消终止全部已排 Source 和等待 resume 的任务，迟到回调由轮次/代次围栏丢弃。

实际页面同时接入旧 WAV 和新 `audio_frame`；部分失败、格式错误、缺帧、断线、退出均清理播放。临时关闭状态 1001/1005/1006/1011/1012/1013 可恢复，正常结束和协议/策略错误不重试；连续建连失败最多三次。主动退出会取消已排重连，旧 socket 回调不能覆盖新连接。

客户端连续播放开关 `VITE_VOICE_CONTINUOUS_PLAYBACK` 与服务端帧开关仍默认关闭。页面复验用进程环境开启，未修改用户主配置。输出时钟修正和重连边界适用于现有 WAV 路径。

## 浏览器发现的缺陷与修复

| 原始证据 | 问题 | 修复与复验 |
| --- | --- | --- |
| browser-protocol-r1 / turn-2 | 直接将 currentTime 与 performance.now 相减，算出的起播早于收到音频，该轮样本丢弃 | 共用 `VoicePcmPlaybackObserver`；输出位置跨过起点后用 getOutputTimestamp 映射，合法样本独立标为 output_pcm。r2 正常三轮及 r3 正常两轮均一轮一份有效报告 |
| r1 / turn-7 | 1011 关闭握手正常，wasClean=true 导致不重连 | 按可恢复关闭状态重试；r2/r3 均保持原页面自动恢复并完成下一轮 |
| r2 / turn-7 | 本地已清理，但断线后无法回传其诊断记录 | 默认关闭的诊断模式另记本地元数据，r3 通过浏览器控制接口取日志，确认 16 个 Source 全清理、待播归零 |

输出时间戳是浏览器对输出流位置的估计，仍不是扬声器物理出声实测。不支持或时间戳不可信时，只报告时间线已跨起点后的观察上界 `scheduled_pcm`；后台回调变慢会使上界变宽，不伪造早起播。`html_playing` 保留。历史 scheduled_pcm 曾在 start(0) 调用时记录，新旧报告不能合并成同一延迟分布；见根 `METRICS_CONTRACT.md`。

技术依据：[MDN currentTime](https://developer.mozilla.org/en-US/docs/Web/API/BaseAudioContext/currentTime)、[MDN getOutputTimestamp](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/getOutputTimestamp)、[IANA 关闭状态登记](https://www.iana.org/assignments/websocket)、[RFC 6455](https://www.rfc-editor.org/rfc/rfc6455.html#section-7.4.1)。按哪些状态重连为本项目选择，标准定义状态含义，不保证服务自动恢复。

## 实际页面复验

真实 React 页面、Codex 内置浏览器、loopback 协议夹具、固定 24kHz 单声道正弦 PCM，无模型、麦克风、生产数据库或凭据。r2 八场景覆盖 WAV、双句帧流、播放中取消、部分失败、错误格式、缺帧、1011 断线和恢复后下一轮；r3 四个针对性场景补测断线本地清理、恢复、已观察输出后取消、取消后下一轮。不是十二个独立用户会话，也不是性能 A/B。

- r2 正常三轮与 r3 正常两轮全部自然排空，各有一份有效 output_pcm 报告；预排时间线最大间隙均为 0ms。这只说明固定片段已及时送达下的时间线连续，不代表真实 TTS 没有欠载或设备无杂音。
- r3 断线清理 16 个仍持有的 Source，本地 Source 清理代码耗时约 0.10ms；已观察浏览器输出后取消，清理剩余 15 个 Source，约 0.50ms；待播数与秒数归零，未观察到取消后旧播放回调。
- 上述小样本是本地节点停止/释放调用耗时，不是停声 P95、服务端资源释放、硬件尾音或正式取消门。
- 部分失败明确提示；错误格式和缺帧停止本轮并提示重新提交。夹具注入的迟到取消/失败文本和音频未重新显示或排播。
- r1 整套原始事件及缺样本负结果保留；未自动重连的第八轮是从记录手动继续，不能将其标作自动恢复。

证据：`runs/20261004-r3/browser-protocol-r1..r3`，包括 events.jsonl、源码 SHA、分析、浏览器本地日志和恢复页面截图。r2 分析不能证明断线瞬间本地清理，须使用 r3 本地记录。

## 回归与自审

72 套件/346 项 fresh 全量后端测试通过；31 项独立前端专项检查通过；最终生产 TypeScript/Vite 构建通过。专项检查包含未来起播不得提前报告、输出位置晚于渲染时钟、后台回调晚到、暂停恢复、等待 resume 时取消、全部未来 Source 停止、容量上限、欠载、旧轮次、帧格式/顺序与重连生命周期。

首轮专项检查 21/22，唯一失败是严格浮点比较；修正测试容差后 22/22。扩展用例曾重复插入四项，35 项日志保留，去重后正式计数为 31。诊断观察器故意抛错的警告属于故障注入，未阻止播放或取消。

同 Agent 自审结论：可进入真实模型完整链路预检，默认新协议仍关闭。没有独立人工评审。暂停/后台、设备输出和正式约 100 次/组的完整模型浏览器性能门尚待完成；真实 ASR 内容也未由本夹具验证。
