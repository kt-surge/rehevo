# 语音会话删除与缓存一致性方案

## 需求与已发现问题

实际 ASR r1 创建了未进入 WebSocket 的会话。DELETE 成功且数据库行已消失，但 Redis 会话缓存仍存在；getSession 优先返回缓存，导致已删除会话仍可读取。缓存 TTL 一小时，正常 WebSocket 结束流程的失效不能覆盖直接删除场景。

成功条件：创建受控会话，不建立 WS、不提交回答、不触发评估；先确认缓存命中，实际 DELETE 成功后数据库与指定缓存都不存在，再次 GET 返回未找到。仅操作本次创建的 ID 和精确缓存键，保留旧实现的失败结果和新实现结果。

## 实现与自评审

保留 Service 事务和关联记录删除顺序，数据库事务提交后再失效对应缓存；回滚不执行失效，未找到时沿用原业务错误。通过 TransactionSynchronization 注册 afterCommit，没有活动同步器时直接失效，便于无代理调用与单元验证。

这里 getSession 的数据库回退不回填缓存，因此“删除提交后失效”可以消除本次已证实的删除残留路径。不宣称解决并发 WebSocket 修改、跨 Redis/数据库原子提交、Redis 故障下自动补偿或所有缓存一致性问题。Redis 操作失败沿用现有异常传播，不静默吞错。

## 验证范围

- 同一真实 REST/Redis/PostgreSQL 链路做前后对照，冻结请求、源码、结果、缓存 EXISTS 与数据库行数。
- 回归覆盖提交前不失效、提交后失效、回滚不失效、数据库删除失败不失效、无同步器正常失效与不存在会话保持业务异常。
- 修改业务后运行全量后端测试；没有前端变更，不追加前端构建。
- 本批无 WebSocket、ASR、TTS、Chat、Embedding 调用；不用真实简历、JD、用户会话，不使用已耗尽的 8 次应用模型授权。

本方案由执行 Agent 自评审。属于 S4 生命周期缺陷修复，不能替代完整出题、评分、训练、复测与六类异步故障验收。
