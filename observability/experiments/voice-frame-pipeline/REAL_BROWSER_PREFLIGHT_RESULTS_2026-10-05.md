# Rehevo 实际语音页面预检与取消确认修复

## 结论和采用决定

额度已找到可用路径：本轮实际使用 qwen3.8-flash、3.1 TTS 和 3.1 ASR 建连。完成真实 React 页 → Spring Boot WS → LLM → TTS → 浏览器输出时钟的预检；12 次受控回答提交全部取得 `output_pcm` 起播观测。输入由 loopback 中继注入公开字幕，无真人麦克风或“说完话后”时延。

已修复相对 WebSocket 接线、识别超时后的主动重连、识别旧回调隔离，以及服务端生成完成后仍播放时的取消确认。选定预设 Skill 的确定性预加载保留为默认关闭候选，帧流和连续排程也继续默认关闭。已完成接线和取消预检，进入正式实验准备；本轮另发现硬截断导致问题不完整，须先处理完整性门。没有证明稳定的浏览器 P95 改善，不能把此前 TTS 组件 P95 降低 52.4% 写成整个语音链路降低 52.4%。原 S0–S4 目标继续 active。

## 真实缺陷、定位及修复

### 1. WebSocket 地址写死端口

原会话响应写死 `ws://localhost:8080`。后端改为相对 `/ws/voice-interview/{id}`，前端按 API origin 解析 ws/wss，Vite 转发 `/ws`。实际两端口页面均已接通。此修复两组共用，不计为帧流延迟收益。

### 2. 已选定岗位仍需模型动态加载 Skill

r1 实际流式请求触发 Spring AI 2.0.0 `OpenAiChatModel$ChunkMerger` 的 `NoSuchElementException`，随后退回非流式。保留原堆栈与 fallback 的实际回复。对照本机 SDK 字节码和 [Spring AI v2.0.0 源码](https://raw.githubusercontent.com/spring-projects/spring-ai/v2.0.0/models/spring-ai-openai/src/main/java/org/springframework/ai/openai/OpenAiChatModel.java)，定位到工具流合并的 Optional 读取；供应商原始工具 SSE 未保存，因此不猜具体缺失字段，也不声称通用兼容问题已解决。

已知岗位不需要由模型再次决定要加载哪个 Skill。候选在服务端从已有 Skill 注册表取 persona，放进冻结模板，并选用注册表的 plain ChatClient。r2–r4 的 11 次后续回答都按 stream 完成，无再次 fallback。这里只能证明本轮路径可用；自定义岗位保留既有路径，预设引用文件正文未提供给模型时也不能称已读取。

### 3. ASR 空闲超时后没有页面恢复入口

实际 3.1 ASR 无音频输入约 23 秒后退出；页面原本一直停在未就绪状态。新增 `asr_unavailable/asr_reconnecting` 和“重新连接语音”按钮，后端复用现有有限重连流程；旧 recognizer 的事件、错误和结束回调不能影响新实例。

r2–r4 共记录 7 次主动重连到就绪，其中多次就绪后能继续提交下一轮受控回答。正常 AI 回复在 ASR 超时那轮仍完成了播放，不能说 ASR 超时中断了回复。这是建连恢复证据，未验证应用 ASR 识别音频、麦克风权限、CER 或识别延迟。永久闲置 ASR 的生命周期和自动恢复策略仍需真实音频验收。

### 4. 已完成生成的轮次不返回播放取消确认

r2 帧流 turn-4 和 r3 整句 turn-3：浏览器已输出且本地停止成功，但服务端已完成生成，`cancelActive().ifPresent(...)` 未执行，因而没有确认。方案见 [CANCEL_CONFIRMATION_DESIGN_2026-10-05.md](CANCEL_CONFIRMATION_DESIGN_2026-10-05.md)。

修复：活动轮次保持原 `turn_cancelled`；已完成/空闲状态按有效请求号返回 `cancel_confirmed/already_terminal`，保留 COMPLETED 终态。客户端按请求号只报告一次往返时间，该确认不清理播放；旧 turnId 的取消确认不得清理新轮次音频。两个确认 Timer 的语义已补入根目录指标契约。

### 旧确认故障复验

`late-confirmation-fixture` 使用真实 React 页和固定正弦 PCM，注入旧轮次 `turn_cancelled` 及无轮次 `cancel_confirmed`。新轮次的 8 个片段完整排程、结束并仅 drained 一次，保留一份有效 output_pcm；没有误取消。此为受控协议正确性证据，无模型性能含义。

- ASR 应用只建连和恢复，没有发送音频，其用量未采集，记 unknown。之前 r4 独立 ASR 内容复核的用量属于另一个封存实验，不能混入本表。
- 分析器首轮误将 startup 元数据当 usage_snapshot，发生 KeyError；源码与错误记录保存。修正后另写 `preflight-analysis-r2.json`，首版分析保留。r2 退出时未留 relay_stop 快照，使用最后真实 terminal 快照；r3/r4 额外保存退出前完整白名单快照。
