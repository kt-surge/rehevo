# Rehevo 手动数据库迁移

应用生产环境不依赖 `ddl-auto=update`。这些文件由维护者在相应版本切换前显式执行，不会由启动过程自动运行。

## 20261001：向量请求版本

字段：`knowledge_bases.vector_generation varchar(36)`，允许 NULL，兼容已有完成文档。新生产者在短事务中分配 UUID 版本并写 PENDING，事务返回后再入队；重试沿用同一版本。正式向量与 COMPLETED 原子提交。

### 切换前检查

1. 停止接收知识库上传/重向量化写入，确认所有旧消费者停止。
2. 导出知识库状态与 Redis Stream 消息、消费组 lag、PEL 清单，保留恢复所需的消息正文及存储文件定位。备份不得进入源码或公开报告。
3. 对无版本的 PENDING/PROCESSING 文档逐项核对：让旧版本完成，或在停写期间建立受控恢复清单。不能通过直接 ACK、删除消息、改成 COMPLETED 来掩盖未完成工作。
4. 正常迁移要求无版本未完成文档已经处理完。SQL 会检查并拒绝这些遗留文档，整个迁移事务回滚。未协调的旧消费者不能继续运行。
5. 执行 `20261001_vector_generation.sql`，核对字段长度、NULL 兼容与原始索引，再切换候选应用。重复执行不会新增字段或分配请求版本。

已有 COMPLETED 文档不需要再次 Embedding，旧无版本消息到达时可跳过确认。未完成无版本消息如果出现在新消费者中，会保持 Pending 并记录需要迁移，不会猜测它属于当前版本。维护者应按恢复清单显式发起新请求，确认完成后再处理旧消息；这是可恢复兼容机制，不能当作自动投递恢复或 outbox。

### 回滚

优先回滚应用并保留兼容的可空字段，避免丢失请求版本历史。需要撤销字段时，先停写及停止所有新旧消费者，确认数据库没有 PENDING/PROCESSING、Redis PEL 与 lag 均为零，并保存版本/消息清单，再执行 `20261001_vector_generation_rollback.sql`。SQL 只检查数据库状态，Redis 门由维护者独立检查；不得把 SQL 成功当成队列已排空。

撤销字段会丢弃历史 generation，正式向量与其他文档字段保持不变。恢复旧应用后才可重新接收写入。不要在需要 `vector_generation` 的新应用仍运行时移除字段。

### 本轮验证范围

真实隔离 PostgreSQL 上验证前向迁移的未完成数据阻断、完成旧数据兼容与重复执行；回滚脚本另验未完成状态阻断与完成后字段移除。版本竞争、重试、完成事务回滚与旧消息保留另有受控实验；具体运行与通过结果见 `observability/experiments/async-reliability/`。生产切换、用户真实库恢复及自动迁移没有执行。

## 20261002：持久化向量任务（候选，默认关闭）

`20261002_vector_tasks.sql` 增加 `kb_vector_tasks`：保存已接受请求的版本、正文、正文指纹、切块配置、投递认领和终态。任务随父文档级联删除。上传的父文档和任务在同一事务接受，Redis 通知在事务返回后发送。

本节对应初始投递阶段；执行租约及持久化业务尝试预算由下一节的追加迁移提供。`APP_AI_RAG_VECTOR_TASK_DURABLE_ENABLED` 仍默认 `false`，不得把投递或单文档重启实验通过当成生产开启许可。完整开启条件见执行租约设计及阶段结果。

### 前向迁移

1. 停止知识库写入口、恢复扫描及所有新旧消费者；备份数据库、对象定位和 Redis 消息/PEL/lag。备份含正文，应保存在受限位置，不进入实验成果。
2. 确认已执行请求版本迁移。对 PENDING/PROCESSING 逐项完成或建立含原正文和切块配置的显式恢复清单；脚本不会为缺失快照的旧任务猜测正文。
3. 执行 `20261002_vector_tasks.sql`。任何未完成父文档没有匹配任务快照时，整个事务拒绝并回滚；已有 COMPLETED 文档可兼容，不触发再次 Embedding。
4. 核对表、索引、原文档与正式向量后启动兼容应用，保持候选开关关闭，直至全部开启门通过。重复执行前向 SQL 不创建新任务或请求版本。

### 回滚

优先保留兼容表、回滚应用及关闭恢复开关。若确需删除表，停止写入、扫描和消费者，确认数据库无 PENDING/PROCESSING 和 ACTIVE 任务，并另外核对 Redis PEL/lag、备份请求清单，再执行 `20261002_vector_tasks_rollback.sql`。SQL 会拒绝未完成父文档或 ACTIVE 任务，但不会核对 Redis。删除表会丢弃正文快照与投递历史，不应在候选扫描或消费者仍运行时执行。

### 已验证范围

仅独立实验库应用前向迁移；隔离影子 schema 验证旧未完成数据阻断、重复迁移、完成旧数据兼容、ACTIVE 任务阻断回滚及终态后撤表。公共实验库保留候选表；没有执行生产迁移或真实用户恢复。结果见 [持久化任务阶段结果](../../../observability/experiments/async-reliability/DURABLE_VECTOR_TASK_RESULTS_2026-10-02.md)。

## 20261002：执行租约与尝试预算（候选，默认关闭）

`20261002_vector_execution.sql` 在持久化任务表追加执行 owner、单调 fence、租约到期时间、已认领尝试次数、固定最大尝试次数及最后执行错误。投递租约与执行租约分别管理：通知可重复，正式提交只接受当前有效执行凭据。认领前递增尝试，默认最多 4 次认领，不等于供应商 HTTP 请求次数。

### 前向迁移

1. 先执行请求版本及持久化任务迁移；停止写入口、消费者、恢复扫描与心跳，备份请求和队列清单。
2. 逐项完成或显式恢复旧 PENDING/PROCESSING 与 ACTIVE 请求。本 SQL 会拒绝任一未完成父文档或 ACTIVE 任务，整个事务回滚；不会猜测旧执行的 owner、租约或已消耗预算。
3. 执行 `20261002_vector_execution.sql`，核对六个字段和预算约束。可在无活动请求时重复执行；已有终态记录兼容且不再次计算。
4. 先保持候选开关关闭。只有完整执行故障、实际入口、配置快照及受控负载门通过并评审后才考虑开启。生产切换未执行。

### 回滚

优先关闭候选开关、回滚应用并保留字段。移除字段时须先停止全部写入、消费者、扫描和心跳，确认数据库无未完成父文档和 ACTIVE 任务，另外检查 Redis PEL/lag 并备份执行历史，再执行 `20261002_vector_execution_rollback.sql`。SQL 不检查 Redis；撤销六个字段会丢失执行权和预算历史，不能在候选应用仍运行时执行。

### 已验证范围

独立实验库仅执行前向迁移；影子 schema 验证未完成请求阻断、终态兼容、重复执行、ACTIVE 阻断回滚及终态后撤字段。真实双消费者使用确定性 VectorStore 检查执行竞争；另以实际应用重启及真实 Embedding 验收未执行请求自动恢复。[计算中真实子 JVM 退出及心跳 SQL 拒绝](../../../observability/experiments/async-reliability/EXECUTION_CRASH_RESULTS_2026-10-02.md)补充验证预算不重置、本地失权及成功恢复后遗留临时块清理。全数据库故障、负载、终态保留及迟到写入对账仍未完成。详见 [执行租约首批结果](../../../observability/experiments/async-reliability/VECTOR_EXECUTION_LEASE_RESULTS_2026-10-02.md)。
